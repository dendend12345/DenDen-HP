### 環境
さくらのゲームサーバー<br>
Forgeテンプレート　16GB

---

さて、今回もお困りの方を見つけてしまいました（義務）

内容は上記の通りでございますが、ただのMODサーバーではありません。<br>
"MODパック" なんですよね。

まあ、まず最初はConoha特有のトラブルかと疑いました。<br>
そうです、MODのアップロードができない、でした。これについては、前回のヘルプデスクをご覧いただければと思います。

[せっかく「Mine and Slash」と「Dungeon Realm」で建てたMODサーバーが起動しない！](https://dendend12345.com/help/mod%E3%82%B5%E3%83%BC%E3%83%90%E3%83%BC%E3%81%8C%E8%B5%B7%E5%8B%95%E4%B8%8D%E5%8F%AF/)

<br>

まあまあ、アップロードできない問題は、例によってSSHで解決できたとして…<br>
なぜこんなに苦戦したのかというと、MODが全部で400個オーバーだったからです。

該当のMODパックは「ATM9」というものでした。<br>
ATM9配布サイトは[こちら](https://www.curseforge.com/minecraft/modpacks/all-the-mods-9)

こんな量のMODのサーバー構築したことねえよ…と思いながらご相談をお伺いしました（怒ってないよ笑）。<br>
最初は「シンプルに時間がかかるのかな～やっぱ400個はきついか～」なんて安直に考えました。

まあ、とりあえずの精神でlogを読んでみます。

しばらく起動させながら眺めても、エラーは出ていないし変なところはなさそうですが、debug.logが途中から一切更新されないみたいでした。<br>
ただ、crash.logは生成されていないので、明示的なエラーではないようです。

本当にサーバー起動頑張っているのか…？と、疑念が出てきました。

とりあえずtopでプロセス一覧を見ることに。
javaが動いているので起動中ではあるが、不自然すぎるほどCPUやメモリ使用率がほぼ0%張り付き。<br>
さすがにおかしいか？いやでも、プロセスは生きている…

詳細を確認するためにps auxをjavaプロセスで絞ってみると、結果はS+。<br>
これはプロセスがイベントの発生を待ってスリープしている状態らしいです。当時はこれが原因か…？と疑っていたのですが、後日検証したところ、Minecraftサーバーは起動の最中だろうが、起動中であろうがS+であるらしいです。なので、これは直接的な原因ではない、と後日談として学びました。

では、さらに検証をしていきましょう。logをとにかく追います。

すると、「travelersbackpack」でログ出力が止まっていることに気が付きました。これに気が付いたときは、これじゃ～ん、と意気揚々としていました。<br>
ここで考えられるのは「travelersbackpack」のロードで止まっているのか、その次に読み込むであろうMOD（ごめんなさい名前忘れました）の読み込む準備でループしたか…

MODパックで競合することは考えにくいので、それぞれのjarファイルが死んでいないか確認することに。<br><br>
・MODなし<br>
・travelersbackpack単体<br>
・名前忘れたMOD単体<br>

この3パターンでサーバーを起動させることに。<br>
しかし、結果は全部無事起動…jarファイルは正常、ということになりました。

じゃあ、メモリが追いつけなくなってループでもしてるか…？と思い、念のため起動構成である「ser_jvm_args.txt」を以下のブログを参考に編集。<br>
（ありがとう、過去の自分）。

[【Minecraft】大量のBotを使ってG1GCの最高の設定を探ってみる](https://dendend12345.com/blog/006-g1gc%E3%81%AB%E3%81%A4%E3%81%84%E3%81%A6bot%E3%81%A7%E6%A4%9C%E8%A8%BC/)

しかし、これも効果なし。<br>
いよいよです、手札が尽きました。

しかし、色々と調べてる間にも起動をあきらめず待機していると、ログが動きました。

```
Failed to write AE2 config
````

おっ？これは…！？<br>
そしてさらに見ていくと…「permission」の文字が。


<br><br>
ｷﾀ━━━━(ﾟ∀ﾟ)━━━━!!
<br><br>


ってやつですね。権限あげましょう。

と、思いましたが「ファイルの所有者あんたやないんかい！」<br>
rootでログインしてるからいけるやん！と思ったので、すぐに落胆することに。

いや、まてよ…

「線状降水帯…うっ・・・！！」<br>
<img src="/images/help/2/nogi.jpg" alt="" style="max-width: 50%; height: auto;"/>

ちゃうちゃう

<br><br><br>

でん：このプロセスの実行者は誰だ…？ログイン者は確かにrootだ。<br>
でん：だが、マイクラサーバーを起動させる時の操作は、Conohaのコンソールだ。

でん：つまり、javaプロセスの実行者がrootである確証はない！<br>
でん：ハヤト！topコマンドを実行してくれ。マイクラサーバーの実行者の確認を！

ハヤト：OK！・・・予想的中、マイクラサーバーの実行者は「minecraft」というユーザーだ。

でん：やはりか…ハヤト！WinSCPで該当のファイルの所有者と権限を確認。

ハヤト：了解！所有者はroot、権限は「rw-rw-r--」。<br>
ハヤト：所有者、もしくは所有者と同じグループに所属するユーザーでないと、このファイルは書き込みができない！

でん：さっきのログは…
```
Failed to write AE2 config
```

<br><br><br>
はいもうここで皆さんの頭にはVIVANTのテーマソングが流れましたね、おめでとうございます。ありがとうございます。

茶番はこの辺にしますが、書いたことは間違いないです。これが原因です。

では、権限を…もしくは所有者の変更でもいいですね。<br>
今回はマイクラサーバーのデータが入っているフォルダの所有者を、javaプロセスの実行者である「minecraft」にしちゃいましょう。

```
sudo chown -R minecraft <ファイルパス>
```

実行後、WinSCPで所有者を確認。<br>
ちゃんとminecraftが所有者になりました。

さあ、改めて…サーバー起動し、待つこと5分

```
Done!
　：
Can't keep up!
```

ログイン確認もでき、これにて解決。<br>
