あ、そうそう。今回の記事はバカ長くなるかもです。マニアな人しか読破できない気がするので、今北産業しときます。

では、本題。

いやいや、テンプレサーバーでしょ？脳死でマウスぽちぽちでいけるっしょ？
と思っていましたが、20分程度待っても状況変わらず…

さすがにおかしいと思って、起動ループにでも陥ったか？と思いながらも、テンプレサーバーだからなぁ…とも思いつつ。

ご相談者様曰く、サポートに問い合わせをしても、「権限とか全部渡したっしょ？だめなら最初から構築しなおしてみな」ってことらしい。

いやいやテンプレなんだからできなきゃあかんやろ何言うとんねん、はよ原因究明手伝えや。

って思いました。正直この対応には幻滅です。ゲームサーバーではかなり人気な会社なので。

まあまあ、こう言われちゃ仕方ないですね。どうにかして、サーバー起動させてやろうと。
完全にオレに任せろ状態、くうううううゲームサーバーオタクの血が騒いでるぅぅぅぅ！！！

じゃあまずはログでも見てみましょうか。
まず目についたのはこれです。

```
Disconnect drom: XXX.XXX.XXX.XXX / 0
```

ちょうどクライアントからサーバーにログインを試みようとして失敗してるみたいですね。
前後のログをみると「Iitialize」で止まっているらしい、ということもわかりました。

ということは、サーバーが立ち上がりきっていない、という推測になります。
サーバー立ち上げでエラーになってタスク終了している、みたいなものはみつからなかったので

・サーバー立ち上げの際にループしてしまっている
・タスクがゾンビ化してしまっている

この2択な気がします。
と思って、直接的な原因をさらに調査。
ログとにらめっこしていたら、！？となる箇所を見つけました。
 
```
Access to the path ”XXXXXXXXXXXX" iｓdenied
```

え？　え？　え？

🥴

いやいや、権限がないって嘘やん。
エビデンスとりましょう。

まずは、サーバーを起動させようとしているOS（ConohaだからUbuntuかな？）のユーザーを見ましょう。
topコマンドで見てみると

``
PID  USER PR NI
XXXX sdtd 20 0 ...
```
まずは、7dtdのサーバーを起動しようとしているユーザーは「sdtd」であることを確認。

そして先ほどアクセス拒否されたファイルの所有者を確認します。
実行コマンドは「ls」にオプション「-ld」を付けます。

```
drwxrwxrx 4 root 4096
```

これやん

実行ユーザーは「sdtd」
読み込みファイルの権限は「root」

契約状態おさらいしますよ？
ConohaのVPS、ゲームサーバー「7 Days to Die」
ボタンぽちぽちでいけるでしょ？テンプレでしょ？
権限がないとか、まじで意味わからんぞ？これじゃ、Conohaで7dtc契約した人全員がサーバー建てれないことになるぞ？ええんか？

とりあえず、目先の問題だけ開発してみましょう。
sudo権限で「chmod」コマンドで叩き、対象フォルダ（配下も全部）にsdtdユーザーに権限を付与してあげましょう。


```
chmod -R a+rwX /home/sdtd/.local/share/7DaysToDie
```

これですべてのユーザーに対して、「/home/sdtd/.local/share/7DaysToDie」フォルダに対して読み書きの権限がついたはずです。

僕が7dtdの知識浅いので、どんなログが出たらサーバー立ち上がったのかわからんのですが、ちゃんと動いてるっぽいし、ログインもできたことを確認したので ﾖｼｯ!

でも、この現象みたことないですか？

[MODパックサーバーが起動しない ～権限編～](https://dendend12345.com/help/002-mod%E3%82%B5%E3%83%BC%E3%83%90%E3%83%BC%E3%81%8C%E8%B5%B7%E5%8B%95%E4%B8%8D%E5%8F%AF%E6%A8%A9%E9%99%90%E4%B8%8D%E8%B6%B3/)

権限足りない系です。
前回の事象はMinecraft、かつMOD入りなのでわからんでもないです。
ただ、今回は素のまま、MODなしの7dtd。

本来ならクーリングオフ案件です。
残念ながらVPSにクーリングオフはないです。泣き寝入り。

僕だったら徹底的に問い合わせをして、ログファイルも提出してConohaに説明ともめます。
それでもだめなら消費者庁に相談知ると思います。
