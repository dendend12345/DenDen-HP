## G1GC
G1GCは「Garbage First Garbage Collector」という用語の略で、Java9から正式に採用された技術です（それまでは「Parallel GC」という技術でした）。そして、Javaのアップデートがするにつれ、内容もアップデートし、現在でも現役の技術です。
メリットは、ポーズ時間を制御しやすく、大規模アプリでも安定して動作し、チューニングによって高いスループット（CPUがアプリの処理にどれだけ時間を使えたか）が得られる、ということです。
デメリットは、設定を誤ると性能が最大限に引き出せなかったり、超低遅延（ゲームや金融取引システム）が求められるケースには不向き、といった点です。

さっそくここで「ゲームには不向き」といった内容がでてきてしまっていますが、決してG1GCを否定しているわけではないです。簡単に説明しておくと、ここでいうゲームは格闘ゲームやレーシングゲームなどを指すことが多く、Minecraftは例外です。Minecraftは処理を「Tick時間」（1Tick=0.05秒=1/20秒）の中でいかに多くの掲載意を終わらせるかが大事になってくるからです。それさえ許容できれば、プレイヤーにはラグとして認識されない、という理由があります。

## ZGC
ZGCは「止まらないGC」を目指して開発されたものです。G1GCとは違い、アプリが動いている最中にもメモリの掃除が進むということです。
メリットとしては、ポーズ時間がとても短く、チューニングはほとんど不要な点です。
デメリットとしては、小規模サーバーではオーバーヘッド（余分な処理やメモリ消費、それに伴う負荷や時間）が起きてしまう、ということです。

今回の検証では、以下のことを観察要点として進めていきます。<br>

今回はいきなりBot100体でやってみます。

### １．オプションなしの起動

```
java -XX:+UseZGC -Xms8G -Xmx8G -jar *******.jar
```

起動時間：10秒程度
